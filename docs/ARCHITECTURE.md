# Архитектура и принципы проектирования SyncWave

SyncWave спроектирован по принципам **Чистой Архитектуры** (Clean Architecture / Ports & Adapters) на языке **Go**. Архитектура гарантирует полную изоляцию бизнес-правил от внешних утилит (`yt-dlp`, `ffmpeg`, SQLite, HTTP-роутинг), легкую тестируемость и минимальное потребление ресурсов.

---

## 1. Доменный слой (`internal/domain/`)

Внутреннее ядро без сторонних зависимостей. Содержит структуры данных и интерфейсы:
- `Track`: Метаданные трека, путь к файлу аудио, путь к обложке, длительность, статус (`ready`, `downloading`, `failed`).
- `Playlist`: Данные плейлиста, интервал автосинхронизации, время последнего обновления.
- `User`: Пользователи, права администратора, хэши паролей.
- `SyncLog` & `SyncProgress`: Модели телеметрии фонового процесса.
- Интерфейсы: `TrackRepository`, `PlaylistRepository`, `UserRepository`, `SettingsRepository`, `SyncLogRepository`.

---

## 2. Слой репозиториев (`internal/repository/sqlite/`)

Реализован на чистом Go-драйвере **`modernc.org/sqlite`** (без CGO):
- **Один файл БД**: База данных хранится в `/data/syncwave.db`.
- **Режим WAL (`journal_mode=WAL`)**: Обеспечивает параллельное чтение несколькими потоками даже во время активных транзакций записи.
- **`busy_timeout(5000)`**: Предотвращает ошибки блокировки базы данных при одновременных запросах.
- **Delta-поиск пачками**: Метод `GetExistingYouTubeIDs` выполняет пакетную проверку (`SELECT youtube_id WHERE youtube_id IN (...)`), находя дельту плейлиста из сотен треков за доли миллисекунды.

## 3. Инфраструктурный слой (`internal/infrastructure/`)

### Движок yt-dlp + FFmpeg (`ytdlp/client.go`)
- **Flat-Playlist Extraction**: Быстрое получение JSON-списка (`--flat-playlist -J`) без загрузки медиа-потоков.
- **Аудио-конвейер**: Скачивание наилучшего аудиопотока, извлечение обложки в JPEG и внедрение ID3-тегов (исполнитель, альбом, год).
- **Обход блокировок**: Подстановка параметров реальных клиентов `--extractor-args "youtube:player_client=android,web"`, проксирование и поддержка сессионных куков.

### Очередь фонового воркера (`worker/queue.go`)
- Ограничение параллельных загрузок до 1–2 потоков.
- Добавление временных пауз (jitter 1.5s) между скачиваниями для защиты IP сервера.
- Передача текущего прогресса (процент, скорость, ETA) в реальном времени.

### SSE Event Hub (`worker/event_hub.go`)
- Thread-safe вещатель событий на базе Go-каналов, рассылающий телеметрию всем подключенным веб-клиентам.

---

## 4. Слой доставки (`internal/delivery/http/`)

- **Маршрутизатор**: `go-chi/chi/v5` с поддержкой подмаршрутов, CORS и защитных middleware.
- **Range-стриминг (RFC 7233)**: Использование стандартного `http.ServeContent`, обеспечивающего моментальную перемотку и докачку чанками (`206 Partial Content`).
- **Single-Binary SPA**: Встраивание собранного фронтенда (`web/dist`) прямо в исполняемый файл через директиву `//go:embed all:dist` с автоматическим fallback на `index.html` для HTML5 History API.
